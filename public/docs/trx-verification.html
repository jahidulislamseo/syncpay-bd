Transaction Verification

Transaction Verification API

Backend-side advanced payment verification — customer-এর MFS transaction আপনার server থেকে সরাসরি verify করুন। Double-spending, fake screenshot ও manually forged transaction থেকে সুরক্ষিত।

কেন Backend Verification?

Frontend-এ transaction ID দেখানো যথেষ্ট নয়। আপনার server থেকে verify না করলে:

  • Fake transaction ID দিয়ে payment এড়ানো যায়
  • Screenshot manipulate করে দেখানো সম্ভব
  • একই transaction একাধিক order-এ ব্যবহার করা যায়
PayFlow MFS প্রতিটি transaction শুধু একবার verify হতে দেয়। duplicate use স্বয়ংক্রিয়ভাবে reject হয়।

Verification Flow

1

Customer Payment করে

Customer bKash/Nagad/Rocket/Upay থেকে আপনার number-এ টাকা পাঠায় এবং Transaction ID দেয়।

2

আপনার Server API Call করে

trx_id, amount ও provider সহ PayFlow MFS API-তে POST request পাঠান।

3

PayFlow SMS Database Check করে

আমাদের agent Android থেকে real SMS data-এর সাথে মিলিয়ে verify করে।

4

Response পাঠায়

verified: true হলে order confirm করুন। false হলে reject করুন।

API Endpoint

POST/verify

Request Body

ParameterTypeবিবরণ
trx_idstringMFS Transaction ID (e.g. 8J1B2C3K4L)required
amountnumberExpected payment amount (BDT)required
providerstringbKash | Nagad | Rocket | Upayrequired
tolerancenumberAmount tolerance in BDT (default: 0)optional
invoice_idstringPayFlow invoice ID (যদি থাকে)optional
 
POST /v1/verify
Authorization: Bearer pf_live_xxx
Content-Type: application/json

{
  "trx_id":   "8J1B2C3K4L",
  "amount":   1500,
  "provider": "bKash",
  "tolerance": 5
}

Verified Response

200 — verified: true 
{
  "success":      true,
  "verified":     true,
  "trx_id":      "8J1B2C3K4L",
  "amount":      1500,
  "provider":    "bKash",
  "sender":      "01XXXXXXXXX",
  "verified_at": "2024-01-15T12:01:43Z"
}

Failed Response

200 — verified: false 
{
  "success":  true,
  "verified": false,
  "error":    "Transaction not found",
  "code":     "TRX_NOT_FOUND"
}

Error Codes

Codeঅর্থ
TRX_NOT_FOUNDTransaction ID আমাদের database-এ নেই
AMOUNT_MISMATCHপাঠানো amount মিলছে না
PROVIDER_MISMATCHProvider mismatch
ALREADY_USEDএই transaction আগেই verify হয়েছে
EXPIREDTransaction 24 ঘণ্টার বেশি পুরনো

Idempotency

প্রতিটি trx_id একবারই verify হতে পারে। একই trx_id দিয়ে দ্বিতীয়বার verify করলে ALREADY_USED error পাবেন। এটি double-spending রোধ করে।

Network error-এর ক্ষেত্রে retry করতে পারেন — একই trx_id verified হলে cached response পাবেন।
